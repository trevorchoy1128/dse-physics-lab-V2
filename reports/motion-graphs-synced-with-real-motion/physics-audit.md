# 物理核數：motion-graphs-synced-with-real-motion
規格：reference/11_Book2_難點與3D模擬器規格.md「模擬器 7　運動線圖與真實運動同步」（第 384–420 行），並用 §0.2、§0.3 通用規範　數據：10 個運行、100 010 幀（每運行 10 001 幀，dt = 0.001 s）　**第 3 輪**（實作版本 0.2.0；數據 2026-09-05 17:05 重新導出，截圖 17:34–17:35）

核數方法：不讀 model.ts / plan.ts / Scene.tsx。自寫 Node 程式（scratchpad/audit3.js，由第 2 輪 audit2.js 改一行：draw 模式的段索引上限由 vt 節點數改為 T，見 §7 第 1 點），按規格方程獨立計算每幀的 s、v、a、路程、速率、線下面積、平均速率、平均速度，再與導出數據逐幀比對。
- live 模式：v = u + at，s = ut + ½at²，a = 參數 a；路程 = ∫|v|dt 用解析式（反向時刻 t₀ = −u/a 分段）。
- draw 模式：v(t) 為以 vt 陣列在整數秒為節點的折線，只取時間窗內 T 段；a = 該段斜率；s、路程按每段梯形解析積分（段內過零另分段）。
- t ≥ T 的凍結幀：預期全部讀數（含 a）保持 t = T⁻ 的值。
- 兩種模式均為解析解，容差取相對誤差 1e-6（分母取 max(1, |預期|)）。

**數據檔是否改變（本輪要求確認）**：index.json 十個運行的 params 與第 2 輪相同，惟五個 random 運行的 `mode` 由 null 改為實際值（random-0/1/3/4 live、random-2 **draw**）。以 audit3.js 重跑後與第 2 輪 audit2-out.json 逐運行比對每個讀數的最大誤差、末幀、反向時刻、箭嘴統計：**九個運行完全相同**（default、四個情境、random-0/1/3/4）；random-2 因模式改為 draw（vt = 預設 [0,1,2,3,3,3,2,1,0,0,0]、T = 5，params 內的 u、a 不生效）而數據不同，本輪按 draw 模式重新核數（見 §1、§2）。抽查幀：default i = 5000（t = 5.000）s = 12.499999999999346、v = 5.000000000000004；scenario-below-axis i = 10000 s = −7.08 × 10⁻¹³、v = −1.9999999999999587、a = −0.3999999999999999；scenario-v-zero-a-not i = 5000 v = −46.05000000000488；與第 2 輪所記數值一致。

## 6. 守恆量與邊界
- 本模擬無守恆量（外加加速度的運動學）。可核的一致性：area ≡ s（100 010 幀差 0）；∫v dt 對 s 漂移 ≤ 3.4 × 10⁻¹¹ m（10 s）；v² = u² + 2as 漂移 ≤ 4.8 × 10⁻¹⁰。
- a = 0、u = 0（scenario-st-not-path）：10 001 幀全部讀數恰為 0，無 NaN。
- draw 模式 T = 5 而 vt 有 11 節點（random-2）：只用前 6 節點，t = 5 凍結 a = 段 [4,5] 斜率 0，s = 10.5、路程 10.5，無 NaN；未見用到窗外節點。
- 參數極端（解析估算，數據內無此運行）：u = ±5、a = ±10、T = 20 → |v| ≤ 205 m s⁻¹、|s| ≤ 2100 m；數值上無溢出。random-3（a = 9.68、T = 5）已見 s = 135.6 m、v = 51.3 m s⁻¹ 正常；scenario-3 軌道軸自動放大到 ±200 m。
- 時間窗末端：t ≥ T 後 t、全部八讀數、兩支箭嘴、標籤全部凍結，0 個不一致；a 保持參數值（F1）。
- 箭嘴像素邊界（F5）：v 箭嘴長度上限（軌道闊度 30%）沒有配合小車位置。在 scenario-3 末端小車距左邊 23%（260 px），箭嘴 282 px 超出 22 px。任何「大負速度＋大負位移」或「大正速度＋大正位移」的運行（即 u、a 同號、|s| 接近軸端）都會出現同一情況；例如 random-3（u = 2.93、a = 9.68、T = 5）末端 s = 135.6、v = 51.3，若軌道軸亦為 ±200，小車距右邊 16%，箭嘴 51.3 × 6.1 ≈ 313 px 也會被截。
- 浮點殘餘顯示（F6）：below-axis 末幀 s = −7.08 × 10⁻¹³ m 是唯一顯示出來的例子；其他運行末幀非零，不受影響。

## 7. 規格待釐清
1. draw 模式 vt 節點數（T + 1 = 11 對應 T = 10）多於時間窗（T = 5）時，實作只用前 T + 1 個節點，t = T 的凍結 a 取窗內末段斜率（random-2 得 0，而非 vt[5]→vt[6] 的 −1）。本核數按此解讀通過；建議 manifest 或規格說明「時間窗外的節點不生效」。
2. random-2 的 params 同時記錄 u = 2.838、a = −3.337（draw 模式下不生效）；導出器宜只記錄生效參數，或註明。
3. 驗證條件三「從未反向時位移讀數與路程讀數必須相等」：物體一直向負方向走時 s = −路程（random-4 全程、random-1 反向前）。本核數以「大小相等」解讀（通過）。建議規格改為「數值上 |s| = 路程」或說明正方向約定。
4. 「由圖生成運動：學生在 v–t 圖上拖曳畫出線段」：實作是每秒一個節點的折線（manifest 已列 beyondSpec）。折線在節點處 a 不連續（scenario-4 於 t ∈ [4, 5) a = −4，其餘 0；random-2 在 t = 3 由 1 跳到 0），a–t 圖出現垂直跳變，是否可接受待老師定奪。
5. 導出的 plan().scales（velocity = acceleration = 0.25，10 運行全同）與畫面實際像素比例無關：scenario-3 畫面比例 6.1 px 每單位，default 24 px 每單位。若 scales 欄位意在讓核數員核對畫面比例，應輸出實際採用的比例（含上限壓縮後的值）。
6. 箭嘴自動比例規則（基準比例、30% 上限、依最大 |v|/|a| 壓縮）規格未定，由開發端設定；本輪發現上限未考慮小車位置（F5），建議規則改為「箭嘴末端不得超出軌道畫布」（例如以 min(30% 闊度, 小車到最近邊緣距離 − 箭頭長) 為上限，或在超出時把箭嘴改畫在小車另一側／只縮短該幀）。
7. 接近零的讀數顯示（F6）：§0.2 第 6 條未規定門檻。建議以當前軸刻度的 10⁻⁶（或絕對 10⁻⁹）為門檻歸零顯示「0.00」，避免學生看到 10⁻¹³ 量級的殘餘。
