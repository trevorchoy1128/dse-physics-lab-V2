核數方法：不讀 model.ts / plan.ts / Scene.tsx。自寫 Node 程式（scratchpad/audit4.js，由第 3 輪 audit3.js 加入兩項：(i) F6 歸零規則的獨立判定——我的解析值 |x| < 10⁻⁹ 的幀，導出值必須恰為 0；解析值 ≥ 10⁻⁹ 的幀，導出值不得為 0，且不得殘留 0 < |x| < 10⁻⁹；(ii) 同一幀內 v、a 兩支箭嘴的比例檢查），按規格方程獨立計算每幀的 s、v、a、路程、速率、線下面積、平均速率、平均速度，再與導出數據逐幀比對。
- live 模式：v = u + at，s = ut + ½at²，a = 參數 a；路程 = ∫|v|dt 用解析式（反向時刻 t₀ = −u/a 分段）。
- draw 模式：v(t) 為以 vt 陣列在整數秒為節點的折線，只取時間窗內 T 段；a = 該段斜率；s、路程按每段梯形解析積分（段內過零另分段）。
- t ≥ T 的凍結幀：預期全部讀數（含 a）保持 t = T⁻ 的值。
- 兩種模式均為解析解，容差取相對誤差 1e-6（分母取 max(1, |預期|)）。
- 截圖：以 Node 解 PNG 逐像素掃描軌道區（綠色 = 箭嘴；任何非灰色 = 有畫任何東西），量度箭嘴起止像素；另以 crop4.ps1 放大四張軌道區（r4-s1end-track.png、r4-s3end-track.png、r4-s4end-track.png、r4-desktop-track.png）。

**數據檔是否改變（模型 0.2.0 → 0.3.0）**：index.json 十個運行的 params 與第 3 輪逐字相同。以 audit4.js 重跑後與第 3 輪 audit3-out.json 逐運行、逐讀數比對「最大誤差、出現時刻、導出值」：**九個運行 80 項全部逐位相同**（default、st-not-path、v-zero-a-not、area-not-distance、random-0…4）；只有 scenario-below-axis 有 4 項改動，全部是 F6 歸零造成（末幀 s、area 由 −7.08 × 10⁻¹³ 變 0，最大誤差幀移到 t = 9.999 s；t = 5.000 s 的 v、speed 由 0 變 0 但我的解析值為 −1.8 × 10⁻¹⁵，記錄為 1.8 × 10⁻¹⁵ 的「誤差」）。即 F6 的模型改動**只影響解析值為 0 的幀**，其他幀不受影響。

## 6. 守恆量與邊界
- 本模擬無守恆量（外加加速度的運動學）。可核的一致性：area ≡ s（100 010 幀差 0）；∫v dt 對 s 漂移 ≤ 3.4 × 10⁻¹¹ m（10 s）；v² = u² + 2as 漂移 ≤ 4.8 × 10⁻¹⁰。
- a = 0、u = 0（scenario-st-not-path）：10 001 幀全部讀數恰為 0，無 NaN。
- F6 歸零門檻 10⁻⁹ m 對物理量的影響：本數據內最小的非零 |s| 是 default i = 1 的 5 × 10⁻⁷ m（½·1·0.001²），draw 運行 i = 1 的 2 × 10⁻³ m；最小非零 |v| 是 v-zero-a-not i = 306 的 1.86 × 10⁻³ m s⁻¹。全部遠大於 10⁻⁹，門檻不會誤傷真實讀數（誤歸零 0 個）。極端情況：live 模式 a = 0.5（最小非零）、u = 0 時 s(0.001) = 2.5 × 10⁻⁷ m，仍高於門檻 250 倍。
- draw 模式 T = 5 而 vt 有 11 節點（random-2）：只用前 6 節點，t = 5 凍結 a = 段 [4,5] 斜率 0，s = 10.5、路程 10.5，無 NaN。
- 參數極端（解析估算，數據內無此運行）：u = ±5、a = ±10、T = 20 → |v| ≤ 205 m s⁻¹、|s| ≤ 2100 m；數值上無溢出。random-3（a = 9.68、T = 5）已見 s = 135.6 m、v = 51.3 m s⁻¹ 正常；scenario-3 軌道軸自動放大到 ±200 m。
- 時間窗末端：t ≥ T 後 t、全部八讀數、兩支箭嘴向量、標籤全部凍結，0 個不一致；a 保持參數值（F1）。
- 箭嘴像素邊界（F5）：scenario-3 末端小車距左邊 259 px，v 箭嘴縮至 239 px，末端 x 37 在畫布內邊 x 17 之內，箭頭與標籤完整。random-3 類型（u、a 同號、|s| 接近軸端）按同一規則亦應可容納，數據內無截圖可證。
- 箭嘴缺失（F7）：只在 draw 模式 t = T 的兩張截圖出現；live 模式 t = T（scenario-3-end）正常。無法從導出數據判斷（plan 向量正常），需開發端在瀏覽器重現：進入情境 1，播放到 t = 10 s 或以「跳到 t =」輸入 10，看小車上方有沒有箭嘴。
- 箭嘴比例隨時間（F8）：規則「至今出現過的最大」使比例單調變小；在 |v| 單調增的運行（default、random-0/3、scenario-3 的 t > 0.61 s）v 箭嘴釘在最大長度，a 箭嘴按 1/|v| 縮小。

## 7. 規格待釐清
1. draw 模式 vt 節點數（T + 1 = 11 對應 T = 10）多於時間窗（T = 5）時，實作只用前 T + 1 個節點，t = T 的凍結 a 取窗內末段斜率（random-2 得 0，而非 vt[5]→vt[6] 的 −1）。本核數按此解讀通過；建議 manifest 或規格說明「時間窗外的節點不生效」。
2. random-2 的 params 同時記錄 u = 2.838、a = −3.337（draw 模式下不生效）；導出器宜只記錄生效參數，或註明。
3. 驗證條件三「從未反向時位移讀數與路程讀數必須相等」：物體一直向負方向走時 s = −路程（random-4 全程、random-1 反向前）。本核數以「大小相等」解讀（通過）。建議規格改為「數值上 |s| = 路程」或說明正方向約定。
4. 「由圖生成運動：學生在 v–t 圖上拖曳畫出線段」：實作是每秒一個節點的折線（manifest 已列 beyondSpec）。折線在節點處 a 不連續（scenario-4 於 t ∈ [4, 5) a = −4，其餘 0；random-2 在 t = 3 由 1 跳到 0），a–t 圖出現垂直跳變，是否可接受待老師定奪。
5. 導出的 plan().scales（velocity = acceleration = 0.25，10 運行全同、全程不變）與畫面實際像素比例無關：畫面比例隨時間改變（scenario-3：a 箭嘴 226 px → 51 px）。若 scales 欄位意在讓核數員核對畫面比例，應輸出每幀實際採用的像素比例（含「至今最大」與邊緣縮短後的值），否則畫面層的 F7、F8 只能靠截圖發現。
6. 箭嘴自動比例規則規格未定。第 3 輪（按預測最大值）的問題是超出畫布（F5）；本輪（按至今最大值 + 邊緣縮短）修好 F5，卻令箭嘴長度不再反映模型的變化（F8）。建議：比例在一個運行內固定，由參數推算（live：max(|u|, |u + aT|) 與 |a|；draw：max|vt| 與最大段斜率），參數中途改變時重算一次；邊緣縮短只在需要的幀施加並保留現有註記。這樣 v 箭嘴隨 v 增長、a 箭嘴恆定，與 v–t、a–t 圖一致。
7. 接近零的讀數顯示（F6）：模型層 10⁻⁹ 門檻已加，但 plan() 的標籤與箭嘴起點應取 observe 歸零後的 s，而非原始狀態，否則軌道標籤與面板不同步（scenario-1-end）。
