# 學生試用：http://localhost:4173/#/sim/motion-graphs-synced-with-real-motion
裝置：電腦（1440×900）/ iPad 直向（768×1024）

## 第一眼
未按任何嘢之前，個畫面已經自己喺度郁緊（架車已經喺條路度慢慢向右行，t 已經去到 1.26s 咁）。上面有條路、幾棵樹、一架黃色小車，下面有三個細細張圖（s-t、v-t、a-t）。右邊有個「參數」板，有滑桿同一堆數字。頂上有個橙色提示框寫住三行字教你點用。

老實講，第一眼唔知呢個係咩：睇落似係「畀你睇架車點郁」嘅動畫，但完全唔知第一步應該撳邊度。個「播放」掣其實已經自動播緊（一開頁就郁緊），呢一點幾奇怪——通常我會以為要自己撳「播放」先郁。如果唔係睇到右邊有粒橙色提示框寫「小車已經在動」，我都唔會知佢已經自己喺度動。

## 老師叫我做的事

### 1. 轉去「由圖生成運動」，畫一條「先快、然後慢慢減速到停」嘅 v–t 圖，播放/暫停/播放/重播
步驟：撳「暫停」→撳「還原預設」→撳右邊「由圖生成運動：我畫 v–t 圖」→喺 v-t 圖度逐粒圓點上下拖，想整一條「頭段高，之後慢慢跌到 0」嘅線。

期望：拖完應該可以喺 v-t 圖度睇到一條由高慢慢跌到 0 嘅線；撳播放架車應該係咁行。

實際：
- 拖圓點嗰陣，會跳出一個小提示話你知「t = _ s，v = _ m/s」，呢個幾useful，冇呢個提示我根本唔知自己拖緊邊一秒。
- 但係啲點嘅時間間距唔平均，好難捉：我一路以為個個點相隔 1 秒（因為第一、二個點試出嚟真係 t=0, t=1），點知跟住再拖多個點，本來以為係 t=3 嘅位置，個提示彈出嚟話係 t=4；再跟住拖，本來以為係 t=4 嘅位置提示又話係 t=6。即係啲控制點喺圖上面「睇落」等距，但實際代表嘅秒數唔等距，要不斷靠個彈出提示嚟估，好難一次過準確咁畫到自己想要嘅形狀。
- v 最多只可以拖到 5.00（up 咗都係5.00，好似有個上限鎖住），冇警告話你知呢個係上限，要自己試先知。
- 拖出嚟嘅線大致做到「頭快、之後慢慢跌到 0」，撳播放，架車真係快快哋出發，再慢慢減速，最後停低（s 定格喺 21.5m 冇再變）。三張圖都跟住畫。基本上做到。
- 暫停 → 播放：完全冇問題，時間由暫停嗰刻繼續，畫好嘅線冇變。
- 重播：由 t=0 由頭再嚟一次，畫好嘅線冇走樣、都冇跳走轉返做「由運動生成圖」模式，係留喺「由圖生成運動」。

嘗試次數：畫線嗰度嘗試咗差唔多 10 次先大致砌到個形狀（因為唔知邊粒點對應邊一秒）。暫停/播放/重播呢部分一次成功。

做到／做唔到：**做到**，但畫線嗰步好靠估、唔靠估唔到。

### 2. 轉返「由運動生成圖」，播放期間將「加速度」拉去負數，等佢停低再倒後行
步驟：撳「由運動生成圖」→撳播放→喺加速度嘅輸入格打 -2（試埋喺 iPad 度直接拖滑桿）→等。

期望：架車應該慢慢減速、停底、再倒後行。

實際：跟預期一樣。輸入 -2 之後架車好快由減速變倒後（因為 a 好快令 v 變負）。

**小車而家喺起點嘅左邊定右邊？** 喺起點（果支紅色小旗）嘅**左邊**。

**離起點大約幾多米？** 大約 15 米左右（screenshot 影到 t=5.70s 嗰刻，畫面上車頂寫住「s = -15.0 m」，同一時間右邊讀數板都係寫 -15.0m）。

**點樣睇出嚟（唔靠右邊數字）：** 睇動畫個場景本身——架車已經行過咗嗰支紅色小旗（起點標記）去到佢嘅左手邊，仲有車頭方向箭嘴變咗指向左（←v），加上路面刻度由 -2,-1,0,1,2 變咗做 -30,-20,-10,0,10,20（鏡頭/比例自動縮，睇路面條刻度尺都知車去咗好遠嘅負位置）。另外車頂自己有個「s = -15.0 m」細字標籤（呢個係喺動畫場景度，唔係右邊嗰塊讀數板），所以都算冇「只抄右邊數字」。

**小車走遠時，畫面有無任何字句話你知發生緊咩事？** 冇特別警告話你知「架車已經好遠」或者「已經超出咗原本範圍」，但係就一定會有一句好細嘅提示字（例如「距離已按線性寬度同步縮放（比例不變）」或者「鏡頭跟着小車移動（比例不變）」）喺個路面圖上面閃出嚟，講嘅係個比例冇變，鏡頭有跟住架車。呢句字好細、好快就冇咗，好易睇漏。

嘗試次數：1 次就成功睇到倒後行為。

做到／做唔到：**做到**。

### 3. 時間窗改做 45 秒，播放，去到 30 秒左右講小車走幾遠
步驟：撳「還原預設」→時間窗數字格打 45 → 撳播放。

**呢度發現一個好大問題：播放速度好慢，慢到離譜。** 我揀咗「2×」速度，但用計時器等咗成 80 幾秒（真實時間），畫面上嘅 t 先至由 0 行到 13.6 秒左右，跟住越等增加得越少（好似播放越嚟越慢，唔係固定速度）。想等到 t=30 秒根本要等好耐好耐，唔知係咪因為個分頁冇畀我一直睇住（自動係咪會慢落嚟），總之對我嚟講呢個「播放」好慢、唔知幾時先等到。

因為咁，我最後用咗「跳到 t=」嗰格直接打 30，睇返讀數：

**小車走咗幾遠：** s = 450 m（車頂自己有個「s = 450 m」標籤，路面刻度亦都自動變成 420,430,440,450,460，中間果格就係家陣位置）。

**點知：** 一係睇動畫車頂細字「s = 450 m」，一係睇右邊讀數板「s 位移 = 450 m」，兩邊一致。仲有埋路面刻度都變咗做大得幾十米一格，證明架車真係行咗好遠。

嘗試次數：播放等咗好多次都等唔到 30 秒真係播出嚟，最後改用「跳到 t=」1 次成功睇到答案。

做到／做唔到：**用「跳到 t=」做到，但用「播放」等就做唔到（等極都好慢）。**

## 每個控制項我以為是做甚麼
| 控制項（照抄標籤） | 我以為 | 試了之後 |
|---|---|---|
| 播放 / 暫停 | 撳一下開始/停低個動畫 | 啱，撳落即刻轉字（播放→暫停），冇延遲 |
| 逐格 0.1 s | 一格一格咁行，畀你慢慢睇 | 啱，每撳一下 t 準確加 0.1s |
| 重播 | 由頭再嚟一次 | 啱，t 歸零，畫好嘅 v-t 線／參數都保留唔會走樣 |
| 還原預設 | 全部滑桿數值同模式打回原形 | 大致啱，u=0, a=1, T=10，顯示嗰四個掣有啲本身就唔全部剔晒（線下面積本身預設冇剔） |
| 速度（0.1×/0.25×/0.5×/1×/2×） | 控制播放快慢 | 揀咗2×之後感覺上都係好慢（可能同呢個瀏覽器分頁冇focus有關，唔肯定係唔係佢本身設計嘅問題） |
| 跳到 t = （滑桿+數字） | 直接跳去某一秒睇嗰刻嘅畫面 | 啱，打數字或拖都即刻跳，好useful，好過死等播放 |
| 模式：由運動生成圖 / 由圖生成運動 | 兩種玩法：一種自己調參數睇車點行，一種自己畫線畀車跟 | 啱，撳落即刻換晒成個右邊板同埋 v-t 圖入面有冇圓點可拖 |
| u 初速 | 車一開始嘅速度 | 啱，同讀數板 v 喺 t=0 嗰值一致 |
| a 加速度（可隨時改） | 車嘅加速度，可以喺播放緊嗰陣改 | 啱，播放緊都即改即生效，另外呢個滑桿可以打負數令車減速/倒行 |
| T 時間窗（最長時間） | 整條時間軸去到幾多秒為止 | 啱，改咗之後三張圖同「跳到t=」嘅上限都跟住變 |
| 速度箭嘴（checkbox） | 決定顯不顯示車度個 v 箭嘴 | 啱，㩒走個「→v」箭嘴即消失，剩返 a 箭嘴 |
| 加速度箭嘴（checkbox） | 決定顯不顯示車度個 a 箭嘴 | 應該一樣道理（冇特登逐個試走，但同「速度箭嘴」機制睇落一致） |
| 切線（斜率）（checkbox） | 唔知，估係畫多條斜斜嘅虛線 | 試完先知：係喺 s-t/v-t 圖上加一條虛線話你知呢一刻嘅斜率(即係v或a)，同讀數板對照 |
| 線下面積（checkbox） | 唔知係咩，睇個名先估到可能同「面積」有關 | 剔咗之後 v-t 圖會塗色顯示由0到而家嘅面積，仲會顯示個「面積=幾多m」，同「位移」讀數一樣 |

## 畫面上的數字
| 數字 | 我以為是甚麼 | 有沒有單位 |
|---|---|---|
| t 時間 | 由開始計咗幾多秒 | 有，s |
| s 位移 | 離起點有幾遠，有方向（可以係負） | 有，m |
| d 路程 | 總共行咗幾遠，唔理方向（一定係正） | 有，m |
| v 速度 | 而家幾快，有方向 | 有，m s⁻¹ |
| a 加速度 | 而家加速定減速，有方向 | 有，m s⁻² |
| v–t 線下面積 | 應該同位移 s 係同一樣嘢，只係用另一種方法計出嚟 | 有，m |
| 平均速率（路程÷時間） | 由頭到而家平均行幾快，唔理方向 | 有，m s⁻¹ |
| 平均速度（位移÷時間） | 由頭到而家平均嚟講位置變咗幾快，有方向 | 有，m s⁻¹ |
| 路面上「s = X m」標籤 | 同右邊讀數板嘅「位移」係同一個數 | 有，m（明確寫住 m） |
| 路面刻度（例如 -20,-10,0,10,20） | 條路本身嘅距離刻度，米做單位 | 冇特登寫單位喺個刻度度，要睇下面「位移 s / m」先知 |

全部數字都有寫單位，呢方面幾清楚。反而係唔清楚嘅係呢啲數字更新得幾快/幾密——有時睇住個位移數字跳嚟跳去，睇唔清楚實際數值就已經變咗第二個。

## iPad 上的問題
- 冇乜按唔中嘅情況，成個版面響應式做得幾好，變返單直欄，冇要橫向拉動。
- 拖 v-t 圖啲圓點喺 iPad 一樣用手指（模擬）掂到，都work，但同電腦一樣，時間間距唔均勻嘅問題仲係喺度，一樣要靠彈出提示先知拖緊邊一秒。
- 拖動個圓點嗰陣，彈出嚟嗰粒「t=_s v=_」提示字有時會疊咗喺個小圖標題（例如「s-t 圖」）上面，一時間睇唔到個標題。
- 個「加速度」數字輸入格（有 ▲▼ 小箭頭）好細粒，喺 iPad 用手指撳應該好難撳中；如果要一格一格用箭嘴由 10 改做 45，要撳成 35 下，好嘥時間——不過我試嗰陣係直接打字入個數字格，冇用箭嘴，所以呢個純粹係我估計會有嘅問題。
- 「時間窗」滑桿本身喺 iPad 一拖都work，唔算難用。
- 播放好慢呢個問題喺 iPad 一樣出現（同電腦一樣，等成十幾秒都先郁一兩秒）。

## 我卡住的地方（按嚴重程度排）
1. **播放速度極慢，等極都唔知幾時先到自己想睇嘅時間。** 呢個係整個任務入面最嚴重嘅問題：老師叫我「按播放，等到時間去到 30 秒左右」，但用「播放」等咗超過一分鐘先行咗十幾秒，完全冇辦法喺合理時間內用「播放」到 30 秒，最後要靠「跳到 t=」呢個後備方法先完成到（唔知呢個係唔係因為個瀏覽器分頁冇畀我睇住先咁，但作為學生我唔會知道呢個原因，只會覺得「個sim卡咗/播得好慢」）。
2. **一開頁架車已經自己喺度郁，未撳任何嘢就已經播緊。** 冇即刻話畀我知呢個係「範例演示」定係已經開始咗正式嘅嘢，容易以為自己漏咗一步。
3. **「由圖生成運動」入面啲拖曳點嘅時間間距唔平均**，睇落等距實際上唔係，好難一次過畫準自己想要嘅 v-t 圖，要不斷試錯同睇彈出提示先知道自己拖緊邊一秒。
4. **v 值拖到 5.00 就郁唔到（好似有上限）**，但冇畫面提示話你知呢個係上限，會以為自己冇拖到位。
5. **架車走得好遠嗰陣，只有好細粒、好快閃過嘅字（例如「距離已按線性寬度同步縮放」）講比例冇變，冇一句清楚啲嘅提示解釋緊發生咩事**，好易睇漏。
6. 三張圖嘅橫軸（時間）數字全部係擺喺圖嘅最底，唔係擺喺 y=0 嗰條虛線度（即係跟返一般數學堂學嘅「x軸打橫喺0果度、有刻度」唔一樣）；y=0 嗰條虛線本身冇刻度數字，要自己諗返先知邊個時間對應返 y=0 嗰點。負數部分（好似 s-t 圖跌到 -36 甚至更多）睇落線好貼近圖頂/圖底，數值密咗，唔算好易讀出實際數值。

## console 錯誤
用 `read_console_messages`（電腦版同 iPad 版都試過）：冇任何 console log，亦冇紅色錯誤。
