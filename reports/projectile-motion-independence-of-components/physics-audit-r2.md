# 物理核數：projectile-motion-independence-of-components（第 2 輪，主實作 v0.2.0）
規格：`reference/11_Book2_難點與3D模擬器規格.md` 模擬器 2（拋體運動：水平與垂直的獨立性）、§0.2–0.3、§4　數據：11 個官方運行（`data/`，每運行 4000 幀，dt = 0.001 s）+ 25 個核數員補跑運行（`audit/extra-data-r2/`，用作者的 model/plan 以自訂參數導出，額外記錄 `plan.bodies` / `plan.trails` / `model.done`；未讀其原始碼），共 36 個運行、144 000 幀

核數程式（全部重寫或重跑，不沿用第 1 輪結果）：
- `audit/audit-r2.mjs`：規格解析解 + 自寫 RK4（子步長 1e-4 s，落地二分至 1e-13 s）；逐幀比對 obs、箭嘴（含本輪的 z 偏移 0.8、3.2 / 2.4 世界單位畫長、y 標籤 x = −3.6）、bodies（ball、gshadow、strobe、shadow、wall、ycol）、trails、done 旗標、縮放、能量、非有限數；官方 8 個運行重匯出與 `data/` 逐幀逐位一致（diffFrames = 0）。結果 `audit/results-r2.json`、`audit/audit-r2.log`。
- `audit/followup-r2.mjs`：對稱（線性內插）、射程、兩球同高、最高點讀數、負角 H、阻力落地時刻、done／時鐘、頻閃間距（由 bodies 反算）、縮放規則。`audit/followup-r2.log`。
- `audit/extra-export-r2.mts`：補跑運行。`audit/lag-check-r2.mjs`、`audit/lag-check-1x-r2.mjs`：在瀏覽器讀 DOM，比對 3D 標籤與讀數。`audit/r2-crop-*.png`：截圖局部放大。

比對準則：無空氣阻力用規格解析解，容許相對誤差 1e-6；有空氣阻力用自寫 RK4（a = −k v|v|，k = 0.01 m⁻¹，manifest.beyondSpec 所述），容許 1e-4；向量加法 1e-9。相對誤差分母取 max(|預期值|, 該量的特徵尺度)（速度 u、長度 max(h, u²/g, 1)、加速度 g、能量 ½u² + gh），以免 vᵧ、y 過零時分母為零。

## 結論
**物理數據、箭嘴（含 F = ma、新畫長、新偏移）、bodies（影子、頻閃、牆上投影、高度影子列）、done 時鐘、參數表、三條驗證條件、三項現象：全部通過。第 1 輪兩項不通過（5.1 現象 1 無截圖、5.3 動能圖刻度）已修正並核實。**

本輪不通過：**5.1a**（畫面，非物理）：情境 1（h = 20 m）的 3D 立體視窗相機固定，球與發射點在框外——`scenario-1-early.png` 3D 視窗只見發射塔與牆，兩顆球（世界 y = 12.78）高於可見頂邊（約 11，由相機參數估算）；`scenario-1-end.png` 3D 視窗路徑由頂邊切入。現象 1 在側視投影與讀數可見（通過），但規格「三個同步顯示」中的立體視角在此情境看不到球。

待前端核對（見 §3 末）：播放中 3D 視窗的 x、y 標籤落後右欄讀數；本輪以單次 DOM 讀取量到落後 0.055 s（0.1×）與 0.65–0.85 s（1×）模擬時間，暫停後兩者逐字相同。第 1 輪修正記錄歸因「擷取時序（Html 覆蓋層與面板非同一幀合成）」——單次 DOM 讀取已排除截圖合成的解釋；餘下可能是無頭瀏覽器軟體繪圖令 3D 幀率低，或 Html 覆蓋層更新滯後，須實機 GPU 播放中核對。

## 7. 規格待釐清

1. **H 公式對負投射角**（同第 1 輪）：H = h + u² sin²θ / 2g 在 θ < 0 時給出高於發射點的值（random-3：43.516 m；θ −30°, h 50：81.86 m），實際最高點是發射點 h。數據採 H = h。建議規格註明 θ < 0 時 H = h。
2. **落地後的讀數約定**（同第 1 輪）：位置與速度凍結在落地瞬間（v = 15.0、vᵧ = −9.64 m s⁻¹），ax、ay 同刻變 0（`ipad-portrait.png` 讀數「a 加速度（垂直）0.00 m s⁻²」而 vᵧ −9.64）。規格未寫；建議老師決定。
3. **θ ≤ 0° 且 h = 0**（同第 1 輪）：飛行時間 0，畫面無動作，讀數（含 vₓ、v、Eₖ）為 0。規格參數表容許 θ 到 −30° 而 h 預設 0；建議 h = 0 時限制 θ ≥ 1°，或提示須設 h > 0。
4. **空氣阻力形式**（同第 1 輪）：a = −k v\|v\|，k = 0.01 m⁻¹（manifest.beyondSpec）；本核數只驗證自洽。u = 50 時起始阻力 > g（第二實作亦提出），待老師定 k。
5. **阻力運行的箭嘴畫長**：規格與本輪改動說明只定無阻力情況（a 3.2、力 2.4 世界單位）；阻力時作者以 g + k(u² + 2gh) 為參考（重量畫長 0.41–1.95），未見文件。不影響物理，建議在 plan 註明規則。
6. **3D 相機與發射高度**：h 大時球出框（§5 1a）。規格「三個同步顯示」未寫相機；建議相機（或 target / fov）隨 h·k 調整，或相機按 k 的規則取景：數據顯示 k = 20 / L、L = max(xMax, 1.3 × yMax)（情境 1：yMax 24.76 m、L 32.18、k 0.6215），即場景本身已預留高度至 20 / 1.3 = 15.4 世界單位，但固定相機（position [8, 6, 22]、target [9, 2.5, −2]、fov 40°）在 z = 0 平面可見頂邊只有約 11 世界單位（由相機參數估算），兩者不一致。
7. **時間軸長度**（同第 1 輪）：meta.tf = 1.5 × 無阻力 tf + 0.3 s（阻力）或 tf + 0.3 s（無阻力），「+0.3 s」與 1.5 倍規格未寫；不影響物理。
