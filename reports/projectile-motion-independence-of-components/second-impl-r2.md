# 第二實作比對：projectile-motion-independence-of-components（閘 2 第 2 輪，主實作 v0.2.0）

積分方法：無空氣阻力 → 規格解析解（x = u cosθ·t，y = h + u sinθ·t − ½gt²，v_y = u sinθ − gt），落地時刻用二次方程精確解；有空氣阻力 → 古典四階 Runge–Kutta（RK4），落地步內以二分法（40 次）對步長分數求 y = 0 的根。
步長：dt = 0.001 s（取自 index.json）。幀數：4000（t = 0 至 3.999 s；落地後 t 凍結，故最後一幀 t 可小於 3.999）。
空氣阻力形式依 manifest.beyondSpec：a = −g ŷ − k v|v|，k = 0.01 m⁻¹，質量 1 kg。
凍結規則（第 1 輪已如此實作，本輪不變）：所有球落地後整個狀態（含 t、tf）凍結在最後一顆球的落地時刻；落地球 y = 0、速度停在落地瞬間、a = 0。

## 結論

**一致。** 11 個運行、138 個（運行 × key，含 frame.t）組合全部通過，7 個落地運行的落地幀索引完全相同，凍結行為兩者相同。

- 無空氣阻力 8 個運行（容限 1e-6）：最大絕對誤差 2.5e-10（random-4 的 Ek，量值約 500，相對 4.7e-13），其餘 ≤ 5.2e-11。
- 有空氣阻力 3 個運行（容限 1e-4）：最大絕對誤差 3.3e-13（t 的累加浮點漂移），x、y、vx、vy、ax、ay、Ek 差 ≤ 2.3e-13。
- 落地時刻：7 個落地運行的落地幀索引相同，落地 t 差 ≤ 3.3e-13 s（容限 2 dt = 0.002 s）；random-1、random-2、random-4 兩者皆在 4 s 內未落地。
- **本輪重點一：drop 運行（scenario-same-landing，u = 10、θ = 0、h = 20）**：xB、yB、EkB 三個 key 與主球 key 全部通過（xB 差恰為 0，yB 差 1.3e-13，EkB 差 9.9e-12）。兩球同時在第 2020 幀落地，t = 2.019275 = √(2h/g)（與解析值差 1.1e-13）。
- **本輪重點二：凍結後 t 不再增加**：7 個落地運行，主實作與第二實作自全部落地幀起，頂層 `t`、`obs.t`、`obs.tf` 及全部 obs key 的後續漂移皆恰為 0，凍結前 t 嚴格遞增，且全程 tf ≡ t。主實作 scenario-same-landing 在第 2020 幀之後 1980 幀全部凍結於 2.0192751093845005 s；default 在第 1966 幀之後凍結於 1.9657113446070662 s。

與第 1 輪一樣，有阻力的三個運行一致到 1e-13，只可能是兩邊都用 RK4、同一 dt；因此逐幀一致本身不證明積分誤差合格，「額外檢查」以 dt/10 收斂測試與 θ = 90° 二次阻力解析解另行驗證。

## 不一致的判斷

無不一致。為確保「一致」不是「同時錯」，以下用規格解析解與極限情況獨立驗證（不經第二實作、直接檢查主實作 data/*.json）：

1. **drop 運行對規格現象 1 的驗證**（scenario-same-landing 主實作數據）：
   - y − yB 全程 **恰為 0**（規格「兩者垂直位置永遠相同」）；xB 全程恰為 0（由靜止釋放）。
   - Ek − EkB − ½u² 全程 ≤ 1.4e-14：水平動能 ½u² 與垂直動能各自獨立相加，符合獨立性。
   - 落地幀 t = 2.0192751093845005，√(2h/g) = 2.019275109384609，差 −1.1e-13；落地 x = 20.19275 = u·t（差 3.9e-13）；落地 v_y = −19.80909 = −√(2gh)（差 5e-13）；落地 EkB = 196.2 = gh（m = 1）。
   - 落地幀與前一幀的 t 差 2.751e-4 s < dt，證明主實作是步內插值求落地時刻而非取整步。
2. **凍結行為對規格的驗證**：規格未定義落地後的行為，但「飛行時間」顯示要求 tf 停在落地時刻。主實作與第二實作都把 t、tf 凍結在最後一顆球的落地時刻，凍結後 ay = 0、y = 0、v 停在落地瞬間值（default 落地 v = 15.000 = u，符合「落地速率等於初速」）。兩者在此點的行為一致到 1e-13。
3. **無阻力運行 vs 規格解析解**：第二實作直接代入規格方程，因此上表誤差即主實作與解析解的差（≤ 2.5e-10）。落地時刻與 (u sinθ + √(u² sin²θ + 2gh))/g 一致到 3e-13。
4. **主實作數據內部一致性**：
   - 無阻力 8 運行 v_x 全程與 v_x(0) 差 0，符合規格驗證條件（容許 1e-6）。
   - 無阻力機械能 Ek + g·y 全程守恆，最大漂移 3.0e-10（random-4）。

## 額外檢查

### 量綱
- x = u cosθ·t：m s⁻¹ · s = m。y 三項：m、m s⁻¹·s、m s⁻²·s² 皆為 m。v_y = u sinθ − gt：m s⁻¹。H = h + u² sin²θ/2g：m + (m² s⁻²)/(m s⁻²) = m。
- 阻力 a = −k v|v|：[k] = m⁻¹，m⁻¹ · (m s⁻¹)² = m s⁻² ✓。終端速率 √(g/k) = 31.32 m s⁻¹；第二實作由 h = 50 向下射（u = 1、θ = −30°）約 3 s 後 v = 24.9，向 31.3 單調趨近。
- Ek = ½mv²，m = 1 kg → J；drop 運行 Ek(0) = 50 = ½·10²、EkB(0) = 0、落地 EkB = gh = 196.2 J ✓。
- 角度：controls 以度輸入，兩實作內部用弧度（default t = 0 幀 vx = 15 cos 40° = 11.4907 一致；drop 運行 θ = 0 → vy(0) = 0、vx(0) = 10）。
- 時間：凍結後 t 的單位與值都不變（無「幀數 × dt」與「落地時刻」混用），tf ≡ t 全程成立。

### 對稱
- R(20°) − R(70°) = −1.8e-15，R(30°) − R(60°) = −3.6e-15（h = 0，無阻力）。
- 掃描 40°、44°、45°、46°、50°：R = 22.587、22.922、22.936、22.922、22.587，45° 最大且對 45° 鏡像相等。
- 上升／下降時間相等（default t_top 0.983 vs tf/2 0.9829，幀解析度內）、落地速率 = 初速。
- drop 運行：主球與 B 的垂直運動完全相同（y ≡ yB），只差水平運動 —— 正是規格要學生看見的對稱。

### 極限
- **t = 0**：所有運行 t = 0 幀零殘差（x = 0、y = h、vx = u cosθ、vy = u sinθ、t = tf = 0；drop 時 xB = 0、yB = h、EkB = 0）。有阻力 θ = 0 時 ax(0) = −k u² = −1.00（u = 10）、ay(0) = −g。
- **θ = 0、h = 0**：一開始已在地面，t = tf = 0、x = y = vx = vy = 0、ax = ay = 0、H = 0，並立即凍結。θ = −30°、h = 0 且 companion = drop 相同，B 亦在地面。h = 0、θ = 40°、companion = drop：主球正常飛行，B 自第一幀起 yB = 0、EkB = 0，整體在主球落地時才凍結。
- **companion = drop、h = 20、θ = 30°**（index.json 無此組合，第二實作自測）：B 在 2.0193 s = √(2h/g) 落地並個別凍結（yB 之後恆為 0），t 繼續前進，主球在 2.923686 s（解析值 2.923686）落地後整體 t 才凍結。此為「凍結時刻 = 最後一顆球落地」規則在兩球落地時刻不同時的行為；index.json 只覆蓋兩球同時落地的 drop 情境（θ = 0），此組合未經兩實作比對。
- **k → 0**（第 1 輪已測）：k = 1e-4、1e-6、1e-8 時與無阻力解析解的差 5.7e-2、5.7e-4、5.7e-6，與 k 成正比，收斂到規格方程。
- **u 很小、有阻力**（u = 1、θ = 45°、h = 5）：落地 t 與無阻力差 8.6e-3 s、x 差 −6.9e-3 m，量級與 k v²/g ≈ 0.1 的修正一致。
- **g 增大 → 飛行時間縮短**：θ = 40°、u = 15 時 g = 9.81 落地 1.9657 s = 2u sinθ/g；g = 1.6 解析 12.05 s，4 s 內未落地，t 走到 3.999 不凍結（與 random-1/2/4 的行為一致）。
- **θ = 90°**：cos 90° 在浮點下為 6e-17，x 全程 ≤ 4e-15，可視為 0。

## 規格待釐清

1. **空氣阻力的形式與係數**：規格只寫「開／關」。兩實作都用 a = −k v|v|、k = 0.01 m⁻¹（終端速率 31.3 m s⁻¹）。u 上限 50 m s⁻¹ 超過終端速率，u = 50 時起始阻力加速度 25 m s⁻² > g。若老師希望阻力只是輕微修正，k 應小一個數量級。
2. **tf 的定義與凍結時刻**：兩實作都令 tf ≡ t 並凍結在**最後一顆**球落地。companion = drop、θ > 0、h > 0 時 B 先落地、主球後落地，主球落地前面板的 tf 隨 t 走、B 已停；規格「飛行時間」要顯示哪顆球的落地時刻未寫。本輪 index.json 的 drop 運行是 θ = 0（兩球同時落地），此分歧情況仍未經兩實作比對，建議下輪加一個 drop、θ > 0、h > 0 的運行。
3. **落地後的狀態**：規格未寫。兩實作都在落地後停在落地瞬間（y = 0、v 保留落地值、a = 0、t 凍結）。落地後 v ≠ 0 而 a = 0 是「凍結顯示」而非物理狀態（真實落地會有碰撞），面板若標示「落地速率」則合理。
4. **「水平初速加倍」的第二顆球**：規格迷思表只說「水平初速不同」，「兩倍」是開發端定的。
5. **h = 0 且 θ ≤ 0**：兩實作都令球一開始在地面（tf = 0，速度歸零）。若老師希望視為無效輸入或允許沿地面運動，需明示。
6. **H 在 θ < 0 時 = h**：規格公式 H = h + u² sin²θ/2g 對 θ < 0 給出大於 h 的值，兩實作都改為 H = h。建議規格註明。
7. **非 observe 輸出的提醒**（第 1 輪已提，本輪數據仍如此）：data 檔 `meta.tf` 在有阻力運行不等於 obs.tf（random-0 的 meta.tf = 5.859，實際落地 3.963），在 drop 運行 meta.tf = 2.319 = 落地 2.019 + 0.3。看來是播放時長而非飛行時間；不在比對範圍，只提醒介面不要把它當飛行時間顯示。
