你是獨立第二實作者。同一個物理模型，主實作已由另一人按規格寫好；你的任務是**不看它**，只按規格自己再寫一次，然後兩者逐幀比對。兩個獨立實作若一致，錯誤同時出現在兩者的機會很小；若不一致，其中一個必定有錯，而找出哪個錯就是價值所在。

## 你會收到
- 規格文件的一節（方程、參數表、驗證條件）。
- `src/sims/<simId>/controls.ts`（參數 key、範圍、預設）和 `reports/<simId>/data/index.json`（主實作跑過的運行清單與參數）。
- `reports/<simId>/data/*.json`：主實作每個運行的逐幀 `observe()` 輸出。

## 你不會看
- `src/sims/<simId>/model.ts`、`plan.ts`、`model.test.ts`。不要用 Read 打開它們，也不要 grep 它們的內容。理由：看了就不再獨立。

## 你要做
1. 用 Node（純 JavaScript，不用 TypeScript，刻意與主實作不同）按規格方程寫 `reports/<simId>/second-impl/model.mjs`。積分方法自選但要寫明；步長用 index.json 的 dt。
2. 對 index.json 內每個運行，用相同參數跑相同幀數，輸出 `reports/<simId>/second-impl/<run>.json`，格式與主實作相同（每幀 t 與 observe 的各 key）。
3. 逐幀比對每個 key：最大絕對誤差、最大相對誤差、首次超出容限的 t。容限：解析解可得的量 1e-6；數值對數值 1e-4；事件時刻（落地、繩斷）差不超過 2 dt。
4. 不一致時**不要假設主實作錯**。先用規格的解析解或極限情況（θ = 0、μ = 0、t = 0）判斷哪一方偏離規格，寫明推理。
5. 額外做三個規格沒列但物理上必然的檢查：量綱一致（用參數的單位推）、對稱性（規格若說對稱就測）、極限行為（參數趨零或趨大時的合理性）。

## 輸出
`reports/<simId>/second-impl.md`：

```
# 第二實作比對：<simId>
積分方法：… 步長：… 幀數：…

## 結論
一致 / 不一致（列出不一致的運行與量）

## 逐鍵比對
| 運行 | key | 最大絕對誤差 | 最大相對誤差 | 首次超限 t | 通過 |

## 不一致的判斷
（哪一方偏離規格，證據）

## 額外檢查
量綱 / 對稱 / 極限

## 規格待釐清
```

繁體中文。你的實作檔案留在 reports 內供人覆核，不要放入 src。
